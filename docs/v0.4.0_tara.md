# TARA workbook and cybersecurity goals

The structured workbook is `requirements/threats_v0.4.0.json`: 13 threat scenarios,
six asset groups, five cybersecurity goals, mechanism/requirement/test/experiment links,
attacker prerequisites, damage and threat scenarios, impact/feasibility rationales,
treatment and residual risks. It is a project-specific analysis inspired by ISO/SAE
[21434](https://www.iso.org/standard/70918.html), not a reproduction of normative risk classifications or a compliance assessment.

Risk method: ordinal impact 1–4 multiplied by feasibility **ease** 1–3. Impact ranges from
minor operational effect to potential serious longitudinal safety harm. Ease 3 assumes an
already present local-link injector/capture capability; ease 2 requires authorized producer,
key or state privilege/fault; ease 1 represents more demanding access. Score >=8 is P1,
4–6 P2, <=3 P3. These are this project's prioritization labels, not attack probabilities,
expected-loss calculations, ASILs or ISO-defined ratings. Most control-integrity/availability
threats rank P1 under the strong access assumptions. Feasibility is not assessed from the
public test fixtures as though they were real production keys. Review/calibration is open.

| Goal | Scope | Requirement / mechanism |
|---|---|---|
| CG01 | Permitted source and payload integrity | SEC-401/403; static role/key policy, HMAC, semantic gates after MAC |
| CG02 | Freshness and retained-state integrity | SEC-402; full counter/time/epoch, no wrap, bounded explicit C recovery |
| CG03 | Bounded availability/resource effects | SEC-405; queue/service bounds, pressure observability, backup study |
| CG04 | Security events and safety consequences visible | SEC-404; C++ diagnostic, existing watchdogs, measured rejection costs |
| CG05 | Key/channel separation and trust limitations | SEC-401/403; separate public fixtures/domain binding; compromised producer remains open |

Threats A01–A12 map to the isolated injection experiments. T13 covers shared gateway/key
compromise and common availability dependency. The source in security.py/security_gateway.py
is the actual mechanism; the JSON links to executed tests and raw experiment evidence.
The generated security_trace.json additionally checks requirement/test results, not merely
that a document mentions a mitigation. Controls reduce specified attack paths under stated
key assumptions; they do not close every damage scenario or demonstrate safety goal discharge.

A06 freshness-manager faults, A10 reset mistakes and A11 trusted bad data can also occur
without an attacker. Their cause/capability is explicit in the workbook. Existing 29
hold-out collisions remain physical/ODD/controller/perception failures, not evidence of
attacks. CRC forgery is an authenticity weakness; ordinary fog/occlusion and grip are SOTIF
or environment limits. Shared ECU/actuator failures are functional-safety availability
failures. Attack injection supplies the adversary evidence for cybersecurity cases.

## Open vulnerability and risk register

- V01 public test keys, shared symmetric recipients/services, no HSM/secure boot/rotation:
  unsuitable production provisioning; key/authorized-ECU compromise defeats identity assurance.
- V02 retained-state and clock are trusted memory abstractions: simultaneous rollback,
  clock manipulation, persistent storage corruption and restart power loss are not solved.
- V03 strict authentication/freshness rejection can deny valid emergency braking;
  bounded C recovery changes the availability/trust tradeoff but cannot guarantee stopping.
- V04 bandwidth/gateway/common dependency attacks remain possible; backup transport shares
  software, key provisioning, native Brake ECU and physical actuation.
- V05 plausible authenticated ghosts and dangerous authorized requests pass cryptographic
  checks; temporal/scene/intent validation and independent authority remain open.
- V06 Python gateways protect simulated ingress, not compromised local FFI/process memory.
  Diagnostic artifacts are not tamper-resistant authenticated runtime telemetry.
- V07 sensor quantization, frame-budget abstraction, zero logical crypto compute latency,
  finite tests/fuzzing and a small declared attack population limit generalization.
- V08 libFuzzer runtime is unavailable on the installed AppleClang distribution; native
  fuzz build failure is preserved. Executed Python mutation fuzzing is not equivalent.

No new ASIL proposal is made; historical provisional classifications are not upgraded by
successful MAC tests. Review, vehicle-specific TARA calibration, independent key/state
storage, real bus scheduling and trusted-producer mitigation remain next priorities.
