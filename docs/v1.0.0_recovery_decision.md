# Candidate recovery and SOTIF design decisions

## REC-501: select newest authenticated command across available transports

Threat: a delayed but still age-valid primary can override a fresher backup under native
primary-first arbitration. Safety rationale: command intent can change inside the 100 ms
security age budget; freshest verified same-producer evidence should be preferred. Both
paths must first pass their own MAC, sender/route, epoch/counter and age checks. Comparison
uses authenticated issued time, never the injector's outer admission time or provenance
label. When backup is newer, suppress only the older primary and use the already verified
backup through existing C++ CRC/counter/payload validation. Equal timestamps retain native
priority; a missing/rejected backup cannot supersede primary. Configuration without B/C
security is rejected. No stale or unauthenticated message is admitted and no fresh request
is invented.

State definition: NO_VALID -> PRIMARY_ONLY/BACKUP_ONLY/BOTH_VALID; BOTH_VALID selects latest
issued timestamp (tie primary); rejected/expired path leaves its valid peer if present;
NO_VALID retains native 100 ms command timeout behavior and supervisor indications. Existing
bounded policy C forward-gap/next-epoch rules remain unchanged. Trusted shared clock, same
logical authorized producer, separate verified ingress and functioning native actuator are
assumptions. Residuals: malicious key holder can sign newer harmful intent; both-path loss,
stale replacement, actuator failure, low grip and insufficient distance remain unmitigated.
Negative tests exercise no authentication, missing/bad backup, equal/older/newer boundary.
This opt-in candidate does not claim to solve the six v0.4 C stale-delivery collisions.

## REC-502: bus-pressure observation and explicit diagnostic recovery

Threat/fault: historical high-water or cumulative drop counts were repeatedly reported as
current pressure after the queue cleared. Use current queue length >24 or new drops, keeping
64-frame queue/four-frame service bounds. NORMAL -> PRESSURE on observed condition;
PRESSURE -> RECOVERING when clear; RECOVERING -> NORMAL after 100 ms continuously clear;
new pressure returns to PRESSURE and restarts dwell. Events occur on transitions. The
native security DTC remains latched until disable, independently of transport recovery;
normal diagnostic recovery never relaxes authentication or initiates braking. Tests show
empty queue with historical high-water is not current pressure and exercise dwell/re-entry.
Residual: queue pressure does not prove malicious cause or safe bandwidth/actuation.

## SOT-501: comparative perception/braking study, no silent default change

Controlled development cases compare legacy union fusion, corroboration-only, two distinct
single-source acquisitions across >=50 ms, confidence lowering below the normal acceptance
threshold and an explicitly capped 3 m/s² demand configuration. The cap study also lowers
planning deceleration and emergency-flag threshold to keep the existing config valid;
its coupled changes are reported, not disguised as an isolated one-line cap. The last four
are study profiles, not the candidate's default perception controller.

Temporal counting uses source acquisition timestamps, not repeated control cycles. Both
positive healthy sources corroborate immediately; missing/uncorroborated evidence is marked
uncertain/unavailable rather than ground-truth free space. Native recovery can add 90 ms
and delay true braking; both collision/missed-intervention and unnecessary-braking outcomes
are required. Persistent consistent ghosts can pass temporal confirmation; corroboration
can miss a true single-source target. Confidence is a toy quality score, not calibrated
probability. Bounded deceleration can reduce false-braking intensity while increasing real
impact risk. No following vehicle exists in this simulator; no rear-impact benefit/risk is
quantified. These tradeoffs preclude adopting a false-positive-only optimized default.
