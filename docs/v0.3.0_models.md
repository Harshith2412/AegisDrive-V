# Model assurance record

The actual official SysML v2 Pilot Implementation was evaluated, downloaded and executed:
[release 2026-09.1](https://github.com/Systems-Modeling/SysML-v2-Pilot-Implementation/releases/tag/2026-09.1),
Jupyter kernel 0.63.1 all-jar with its bundled standard libraries. Java 21 is used directly
through `tools/sysml/ValidateSysML.java`; no notebook installation, API server or proprietary
license is required. Download and jar hashes plus Java version are recorded in environment.json.
The published distribution is a development language implementation, not a qualified safety tool.

`models/v0.3.0/aegis.sysml` contains typed camera/radar observations, fusion, ADAS decision and
supervisor decomposition, independent transport usages, Brake ECU, Body ECU, achieved-deceleration
sensor and connections. `requirements.sysml` contains all 44 requirement usages, component
allocations and corresponding verification usages with verify relationships. Test IDs in
documentation link to external executed results; these SysML verification usages are not
executed by the validator and do not assign invented pass verdicts.

An abstract state lifecycle is represented using genuine state/transition definitions.
It intentionally contains a representative path rather than the complete guarded controller.
The existing PlantUML model retains all 26 legal API transition edges, cross-checked against
C++; neither model establishes behavioral equivalence or model-checks timing/guards. Units
remain explicit in field names rather than fully quantity-typed; this is incomplete semantic
engineering even when language validation succeeds.

The wrapper calls the pilot's `parse` and `validate`, loading bundled standard libraries.
Cross-package files are loaded together as one textual validation resource. A reserved
identifier (`state`) and a first attempt at per-resource cross-package validation initially
failed; failure logs remain. The final resource has **zero syntax/semantic errors and zero
warnings**. A separate model with `NonexistentType` must be rejected with an unresolved-type
diagnostic, demonstrating that the check is not merely brace matching or a string linter.
`results/v0.3.0/sysml-validation.log` and `sysml-negative.log` are the actual outputs.

The original v0.2.0 structural model also passed the pilot in this session; historical
v0.2.0 records saying unvalidated are retained as historical evidence, not rewritten.
The new fault-containment PlantUML diagram is parsed and rendered to SVG using PlantUML
1.2026.2/Smetana. Original five UML artifacts remain intact in the archive; the legal-state
edges are checked again by `tools/check_v3.py`.

Parser/semantic validity establishes only that the submitted model conforms to the checks
implemented by this pilot and its libraries. It does not demonstrate completeness, physical
independence, satisfaction of requirements, adequate hazard mitigation or production safety.
