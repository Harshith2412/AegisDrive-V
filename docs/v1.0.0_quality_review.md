# Code, model and dependency quality review

The native ECU core/C ABI source is unchanged from the frozen v0.4.0 archive; candidate
changes are scoped Python route arbitration, diagnostic observation/recovery, study options
and verification/reviewer artifacts. Native Clang static analysis executed for six source
files with no reported diagnostics. This is not MISRA verification or proof of absence of
memory/logic defects. Normal builds retain strict warnings and C ABI version/size checks.
New tests exercise each null step argument, closed/double-closed Python handles, invalid
struct indices and independent generated contact oracles; arbitrary forged native pointers
remain outside the trusted FFI contract.

UBSan executed the native suite (46 tests) and Python integration suite (54 tests) with
halt-on-error and no reported UB. Review-specific tests were rerun against the UBSan shared
library after pointer-oracle expansion. ASan+UBSan builds succeeded, but ASan execution
stalled before any application output. Both a minimal ASan smoke program and native suite
timed out; verbose smoke output stops at interceptor initialization. Exact cause is not
established. No ASan/leak-clean or memory-safety guarantee is claimed. The unsupported native
libFuzzer runtime finding from v0.4 remains open; no native fuzz run is invented.

The current Python envelope parser was exercised with 100,000 fixed-seed random/mutated
inputs and 20 explicitly labeled policy vectors, plus existing Hypothesis mutation and new
stateful monotonic-sequence properties. Known oracle admission matches are not safe-intent
classification: A12 correct-key malicious intent is allowed by authenticity and remains
hazardous. Counts are finite tests, not attack probability. Full envelope/state/clock/key
lifecycle assumptions and 64-byte CAN FD framing remain as documented in v0.4 design.

The dependency advisory tool initially reported eight entries for pip 26.0 (four unique
PYSEC IDs with duplicate entries). Reports are preserved. Only the venv pip was updated to
26.2.2; the remediated advisory query reported no known vulnerabilities. That finding is
conditional on the queried advisory service/date and installed versions, not proof of secure
dependencies. The query covers Python package advisories, not OS/native-library vulnerabilities. Runtime scientific packages/controller thresholds were not changed to repair
outcomes. Public test fixtures, optional unexecuted GoogleTest fetching, upstream tools,
clock/retained-state abstraction and local process trust remain supply-chain/security limits.

Coverage reports separate native six-source-file structural evidence and Python review/
security modules. Native partial MC/DC improves through meaningful C ABI invalid-input
oracles; remaining conditions and source-denominator scope are explicit. Python branch
coverage is not MC/DC. Coverage gaps are not removed by deleting code or weakening behavior.

Official pilot validation loads preserved architecture/requirements/security models plus a
review extension. All 53 requirement usages are present across the four files, but abstract
state graphs, untyped physical units in some fields, no complete guarded behavioral
equivalence and external rather than executed SysML verification remain modeling gaps.
The review extension correctly scopes subjects to route selector, pressure monitor, study
and independent-oracle components. Diagram/parser validity is supporting evidence, not
proof of engineering completeness. The separate lifecycle audit retains five explicit gaps.
