# AegisDrive-V v0.3.0 — technical release report

**ADAS SOTIF, Fault Tolerance & Model Assurance.** Educational research release,
November 1, 2026, America/New_York. No automotive certification, production readiness,
ISO 26262/21448 compliance or substantiated ASIL allocation is claimed.

## Audit and implementation

The existing repository was continued; v0.2.0 source and raw evidence are archived and
byte-checked. Its 62 tests and original experiments were reproduced before editing.
The source audit documented noise-only seed diversity, friction-blind planning, endpoint
contact detection, horizon overrun, warning ODD escape and limits of acknowledgment/status
assurance. The simulation now resolves first contact within a step, splits at stopping
times and stops at the declared horizon. Physical deceleration remains mu*g-limited.
Planning retains the explicit 4 m/s² assumption; no ground-truth grip is passed to ADAS.

The new camera has its own sampling/noise/probability/FOV/latency/confidence/timestamps and
failure hooks. Fusion validates and aligns sampled data, rejects unresolved disagreement
and permits explicitly degraded single-source operation. It is not image processing or
an empirically calibrated confidence estimator. Independent RNG streams do not establish
real-world sensor independence. The backup command channel has independent C++ E2E state
but shares the Brake ECU and actuator. Achieved-deceleration supervision uses the prior
plant interval via an ideal independent-input abstraction; it cannot create grip or supply
failed actuation. ABI 3 reflects new ECU input contracts; existing CAN payloads are retained.

## Quantitative results and limits

- FI01 radar-only remains 20/20 collisions. Camera-only/combined healthy-camera variants
  avoid collision in 20/20 tested seeds, with minimum separation about 5.34 m. Radar freeze
  is detected at 2.11 s: 110 ms from freeze onset, 160 ms from last sample.
- FI02 primary-only remains 20/20 collisions. Combined+backup avoids collision in 20/20
  tested seeds, minimum separation about 5.25 m. This is command-transport fault tolerance,
  not backup physical braking or resolution of every FI02-related failure mode.
- Brake ECU failure and actuator failure still collide 10/10 each. Feedback loss alone is
  indicated while successful demand delivery can continue. Both-channel/sensor loss,
  disagreement and common-mode errors retain unsafe cases in the report.
- No-target nominal cases do not intervene, but plausible isolated radar ghosts and common
  ghosts cause false braking 10/10. Union fusion improves recall while leaving this hazard
  open. A second sensor does not automatically make a target trustworthy.
- Development samples retain 10/48 collisions; hold-out samples retain 29/120, conditional
  on the artificial parameter distribution. The hold-out Wilson 95% interval is about
  17.4–32.6%; it is not a real traffic collision-probability estimate.
- Original nominal scenarios retain avoidance and zero S04 retriggers across tested seeds.
  Combined+backup S02 minimum separation is 7.354 m versus baseline 7.771 m: fusion slightly
  reduces this clearance, despite remaining collision-free. S03 improves 4.888 to 5.237 m;
  S04 remains about 20.263 m. Radar-only S02 retains the baseline clearance. No uniform
  performance improvement is claimed; evaluation.md retains all configuration comparisons.

Final source coverage is **98.32% lines, 86.78% branches, 65.13% MC/DC conditions**
(127/195 instrumented conditions). Baseline was 98.22% lines, 80.30% branches and 45.00%
MC/DC conditions (81/180). Same six-file scope, but source and test sets differ; percentages
are not a like-for-like proof of assurance improvement. Sixty-eight instrumented conditions
remain uncovered. Independent invalid-configuration/input cases and backup validation
exercise safety contracts; implementation was not rewritten simply to raise percentages.
The inventory names every measured decision and uncovered condition. Header inline code,
Python logic and uninstrumented dependencies are outside the six-source-file denominator.

## Open issues and next priorities

| Issue | Status and next engineering work |
|---|---|
| Sensor independence / common cause | OPEN: shared scene/time/simulator; validate diverse hardware, power, confidence and association |
| False targets / ambiguous disagreement | OPEN: isolated ghosts trigger braking; rejecting disagreement can miss real hazards; temporal/scene evidence needed |
| Shared Brake ECU / actuator | OPEN: failures remain unmitigated; independent authority and physical braking path required for stronger claims |
| Delayed accepted demand | OPEN: CRC/modulo counters are not age/authentication contracts; valid old primary can override fresher backup |
| Low grip / short distance / ODD exit | OPEN: achievable braking can be insufficient; no friction estimator or alternate maneuver |
| Fallback safety and driver interaction | OPEN: no universal blind-braking policy, real FTTI or driver/follower rescue study |
| Achieved-decel sensor fidelity | OPEN: ideal previous-plant sample; IMU noise, grade, calibration, correlation and failure study absent |
| MBSE completeness | OPEN: language-valid models have partial abstract behavior, name-encoded units and external rather than executed verification cases |
| Structural coverage | OPEN: 68 instrumented MC/DC conditions plus excluded constructs; no tool qualification or adequacy claim |
| Evidence generalization | OPEN: narrow single-target toy population, 120 hold-outs and artificial distributions; no real-world exposure/field validation |
| Cybersecurity | OPEN: recomputed-CRC forgery remains accepted; not confused with SOTIF or random fault tolerance |
| Real-time/network fidelity | OPEN: host FFI CPU duration and scheduled queues are not target WCET/CAN arbitration assurance |

Highest priorities are target-confidence/false-positive tradeoffs, independent brake authority,
common-cause/fallback analysis, physical sensing/actuation validation and broader scenario
populations. Detailed artifacts: v0.3.0_audit.md, v0.3.0_sotif.md,
v0.3.0_fault_containment.md, v0.3.0_models.md, v0.3.0_verification.md and
results/v0.3.0/evaluation.md. These unresolved issues are part of the release record.
