# AegisDrive-V v0.4.0 — technical release report

**Automotive Cybersecurity and Safety-Security Co-Engineering.** Educational research
release, November 1, 2026 (America/New_York). This release makes no automotive certification,
production-readiness, full ISO/SAE 21434 compliance or production AUTOSAR SecOC conformance
claim. Public test keys and trusted local gateway/clock/state abstractions are explicit.

## Baseline and scope

The existing project was continued, not recreated. v0.3.0 source/raw evidence are archived
with SHA-256; all older hashed baselines remain intact. The unchanged native CMake build and
79 baseline tests passed. All 828 prior runs reproduce every original non-host-timing output
with zero mismatches. All 120 original hold-out inputs/seeds are locked and byte checked.
No project Git history existed, so no tag was invented. Root-cause attribution of the 29
existing collisions is documented: 15 insufficient-distance lower-bound cases, 7 activation
ODD exclusions, 5 low-grip planning-assumption cases, 2 remaining controller/perception/timing
interactions. These are hierarchical engineering groups, not cyberattack findings or unique
causal proofs; counterfactual outcomes and contributing factors are retained.

The new security boundary is implemented in Python SiL ingress adapters ahead of real native
C++ ADAS/Brake/Body interfaces. It protects command, state/feedback and sensor PDUs using
standard-library HMAC-SHA256, 128-bit tags, static sender/destination/message/key policies,
64-bit counters, 32-bit retained-epoch abstraction and authenticated time. Each protected
PDU fits **exactly one 64-byte CAN FD payload**. Native 8-byte CRC/counter and semantic
validation remain active. The C++ ADAS supervisor latches a security diagnostic through
ABI 4 without starting blind braking. Trusted local FFI, IMU/plant and process memory are
not cryptographically protected. No custom cryptographic primitive is implemented.

## Quantitative findings: improvements and costs

A uses original unauthenticated payloads/E2E. B adds authentication/strict freshness. C retains
authentication but permits explicitly bounded authenticated forward/next-epoch recovery.
Matched comparisons use the same bounded frame fabric; original v0.3 is reproduced separately.

- A01 sensor spoof, A03 unauthorized command and A04 payload modification cause achieved
  unnecessary braking in 5/5 A runs each; B/C eliminate it in those tested cases. Native
  acceptance, gateway acceptance and physical consequence are reported separately.
- A02 captured commands can align with modulo-16 native freshness and be accepted in A.
  B/C reject the stale replay. If the attacker replaces/withholds fresh emergency commands,
  collision still occurs in 5/5 B/C runs: integrity success does not restore availability.
- A06 authenticated freshness-manager desynchronization causes 5/5 collisions with strict B;
  bounded C forward recovery avoids collision in these 5 tested runs. A10 same-epoch rollback
  similarly exposes B availability loss; C's explicit retained-epoch restart recovers the
  tested case. Complete retained-state loss remains replay-vulnerable and is characterized.
- A12 authorized compromised ADAS commands cause unnecessary braking in 5/5 for A, B and C.
  Shared signing compromise on both paths remains hazardous. Correct MAC is not correct intent.
- No correctly formed in-policy legitimate message is rejected in the tested attack-free
  B/C runs. Under corrupted tags, delay, desynchronization and congestion, legitimate-demand
  loss remains measurable. Correct rejection of a corrupted tag is not a cryptographic
  false positive; operational availability cost is reported separately.
- Locked old hold-outs remain **29/120 collisions in A/B/C**. On the 48 separate security
  hold-outs, collisions are **0/48 A, 12/48 B, 6/48 C**, while achieved unnecessary braking
  is **15/48 A, 3/48 B, 3/48 C**. Neither collision count alone nor a blanket attack-rejection
  rate adequately expresses the safety-security tradeoff.
- Host verifier CPU duration averages about **5.3 µs** per verification in the declared
  hold-out runs; exact means/maxima, signer overhead and native FFI times are retained.
  These are process CPU measurements under this host, not target ECU WCET, and crypto
  computation is not inserted as actual scheduling latency into logical simulation time.

Counts apply to local toy scenarios, declared attacker capabilities and artificial parameter
samples. Packet observations are correlated and not independent security trials. No zero
attack probability, real traffic collision probability or general safety improvement is
claimed. Protected command/status framing adds 56 bytes over the original eight bytes;
frame-budget scheduling is not a real CAN FD airtime demonstration. Sensor float32 wire
quantization differs from A's float64 direct values and can affect small timing/gap details.

## Open vulnerabilities, safety issues and next priorities

Public fixtures are not production keys. Independent secure provisioning/rotation/revocation,
durable tamper-resistant freshness storage, trusted clock/secure boot, receiver total-reset
protection and shared-service compromise containment remain open. Symmetric recipients can
impersonate a shared-key source. Authorized malicious intent and authenticated plausible
perception errors are not solved by HMAC. Rejecting all available inputs can leave collision
unmitigated; backup transport is not independent security authority or physical braking.

Original grip/ODD/short-gap/SOTIF limitations, shared ECU/actuator failures and ghosts remain
visible. No new ASIL is assigned. Broader threat/access validation, real network timing,
independent command-intent supervision, hardware/key/state implementation and target execution
measurements precede any stronger claim. See the TARA risk register and eight-case interaction
matrix for treatments/residuals rather than interpreting this release as a closed assurance case.
