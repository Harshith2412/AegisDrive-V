# Executive engineering summary

AegisDrive-V v1.0.0 is a reproducible, reviewable educational automotive engineering case
study, not a claim of acceptable vehicle risk or production readiness. The existing C++
ECUs and Python SiL were continued. v0.4.0 was frozen and independently re-executed in a
separate review role: 92 tests passed, 846 prior non-host-timing outcomes matched, and model
validation/hash checks were reproduced. Every strict/recovery security hold-out collision
has an individual sensor-to-impact timeline before control changes.

Twelve strict failures group into six stale-delivery, four counter-gap and two restart/
rollback cases; recovery retains the same six stale-delivery cases. Missing all fresh usable
commands cannot be solved by silently accepting replay. The candidate therefore makes only
two bounded changes: newest-authenticated request selection across valid transports and
correct current-pressure/clear-dwell diagnostics. It retains the original default fusion
because controlled alternatives demonstrate false-positive/false-negative tradeoffs.

Final evidence has 100 passing tests, 53 requirements with passing linked tests, 200 controlled
perception/braking runs, 216 prior locked-set candidate regressions and 297 actual supported
archived/current version-comparison runs. Of 108 predefined final cases, v0.4 and candidate
both collide in 47; actual v0.3 executes only 81 common supported cases, with 27 security
cases explicitly unsupported. The common comparison and all severity/availability metrics
are separate. No aggregate collision reduction or real-world rate is claimed. Original
29/120 and 12/48 strict /6/48 recovery counterexamples remain.

Official SysML semantic validation, an explicit assurance argument, lifecycle gaps/objective
flags, static analyzer/UBSan evidence, finite fuzzing and dependency reports support review.
ASan builds but the runtime/smoke tests time out; no ASan-clean finding is claimed. Partial
native MC/DC remains, and Python branch coverage is separately scoped. Five lifecycle gaps
and all shared actuation, ghost, trusted compromise, timing, storage and simulation limits
are explicit. Portfolio presentation, demo script, reviewer workflow and resume summary
are included without implying certification, external accreditation or actual deployment.
