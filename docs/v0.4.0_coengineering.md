# Safety-security interaction and fault containment matrix

Integrity, authenticity, freshness, availability, functional safety and SOTIF are different
properties. A rejected packet may improve integrity while removing the only usable brake
command. Security diagnostics do not initiate emergency braking. Ordinary safety watchdogs,
fusion validity and achieved-deceleration checks remain active. Every case below has matched
A/B/C raw results, ECU/perception state sequences, native DTCs, gateway decisions, timing,
minimum separation and collision/unnecessary-braking outcomes in experiment_runs.json.

Detection/response are reported separately: earliest verifier/pressure event, earliest C++
security DTC, native feedback fault, command request and achieved braking. Times use simulation
start; subtract the stored injection onset. C++ event latching may occur one control cycle
after a request rejected later in that step. A RESYNC event can latch a diagnostic while
successful braking continues. No universal statement that all diagnostics require AEB
release or that rejection is always safe is made. Security alert is not itself AEB unavailability.

Fault containment: primary/backup have distinct message-domain keys and verification state,
but share Python code/provisioning/clock and native Brake ECU/actuator. Shared key compromise
is explicitly injected; it is not prevented by calling two transports redundant. Status
broadcast receivers have independent replay state but share the symmetric status key and
therefore cannot provide nonrepudiation against each other. Local FFI/IMU/process compromise
is outside this gateway boundary. Ordinary hardware failure, grip/ODD limits and perception
ghosts remain visible alongside the security cases; none is relabeled an attack without
an explicit injected adversary path.

## Focused security FMEA / qualitative tree update

| Failure | Local effect -> hazard | Detection/treatment | Open limit |
|---|---|---|---|
| Bad tag / wrong key | Legitimate demand rejected -> HE-04 | MAC diagnostic, native timeout, independent healthy transport | Common security dependence or no backup still defeats braking |
| Freshness desynchronization | Valid demand rejected -> HE-04 | Strict B vs bounded C measured | Arbitrary/large state loss needs explicit reprovisioning |
| Full retained-state rollback | Previously seen packet can look new -> HE-02/04 | Retained-store reconstruction tested | New empty store replay acceptance is explicitly characterized |
| Shared gateway/key compromise | Both paths unavailable or authentic dangerous demand -> HE-02/04 | Common-case experiments | No independent secure actuation authority |
| Diagnostics saturation | Recent events overwritten | 128-entry buffer, aggregate counters | No tamper-resistant audit log or external authenticated telemetry |

Collision top event retains existing perception/grip/ODD/physical branches. Security adds
loss of usable command/status through withholding, bad authentication, state divergence,
gateway failure or congestion. Unauthorized harmful braking can follow unauthenticated
injection, valid-key compromise or semantic perception error; MAC only addresses specified
unauthorized modification/source paths. Shared key/service/clock/actuator dependencies
invalidate claims of independent redundant cut sets. No numerical attack or failure
probabilities, independence assumptions or full fault-tree completeness are asserted.
