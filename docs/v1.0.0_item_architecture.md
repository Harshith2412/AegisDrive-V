# Current item, ODD and architecture

The item assists an enabled, inattentive ego driver with longitudinal AEB for one relevant
in-path passenger vehicle on a straight, flat road. Native C++ ADAS, Brake and Body ECUs
are called by Python through checked ABI 4 structs. Perception is simulated radar/camera,
not image processing; one target has range/range-rate, presence, health/confidence and
acquisition timestamps. Controller activation is 10–80 km/h; established braking can
continue below 10 km/h. Dry friction >=0.8 is nominal; wet/low-grip, fault and attack studies
do not expand the nominal ODD. The predictor assumes 4 m/s² and has no measured friction
estimator; the point-mass plant limits braking to mu*9.81 and never reverses.

A 10 ms control step samples cached/new sensor output, validates/aligns perception, steps
native ADAS, delivers prior commands to Brake, processes status/lamps and integrates motion
to first contact or the horizon. Radar defaults 50 ms sampling; camera 50 ms plus 80 ms
delivery. Fusion validates acquisition age (150 ms), not merely a fresh authentication send
time. Actuator buildup is a first-order 150 ms lag before friction saturation. Driver brake
arbitration takes maximum demand; simulated driver does not react and holds a completed stop.
No steering, grade, tire dynamics, multiobject/path association, real CAN contention, injury,
following vehicle or real target scheduling model is present.

The security adapter models fixed 64-byte CAN FD envelopes with HMAC-SHA256, role/domain
policy, full counter/time/epoch checks and public test fixtures. C uses bounded authenticated
forward/next-epoch recovery. Wire protocol/domain remains the compatible v0.4 educational
format; a v1.0 project label is not a new security protocol. Local FFI, process, clock,
ideal previous-step achieved-deceleration input and retained-state abstraction are trusted.
Primary and backup command transports share software/provisioning and one native Brake ECU
and physical actuator. They are not independent braking authority or hardware redundancy.

Candidate opt-in `prefer_latest_authenticated` selects the more recent authenticated issued
time across valid routes before native CRC/counter validation. No authentication or replay
gate is weakened. Pressure diagnostics use current backlog/new drops and a separate 100 ms
clear-dwell state machine; native DTC latching remains until disable. Default perception is
legacy union; temporal/corroboration/confidence/capped-braking profiles are studies only.

Architecture sources: models/v0.3.0/aegis.sysml, models/v0.4.0/security.sysml,
models/v1.0.0/review.sysml and the trust-boundary/candidate/recovery UML diagrams. These
complement rather than supersede physical limitations; abstract models are not executable
behavioral equivalence proofs. See lifecycle_trace.md for explicit derivation/model gaps.
