# Reproduction and toolchain

v0.2.0 source and evidence were archived before edits in
baseline/v0.2.0/source-and-evidence.tar.gz with SHA256SUMS. The unchanged baseline was
rebuilt and rerun locally: 39 C++ and 23 Python tests, six scenarios ×20 seeds and the
original 16-point speed/friction sweep ×20 seeds. Actual output is under
results/v0.3.0/baseline. The archive and every historical v0.2.0 result/scenario file are
checked for byte equality by tools/check_v3.py (AppleDouble archive metadata ignored).
The inherited home-level Git repository has no project commits; no tags were created.
Source manifests and archives, rather than nonexistent commit IDs, identify this work.

The current toolchain is macOS arm64, AppleClang 17.0.0, CMake 4.2.3, Python 3.14.3,
Java 21.0.10, PlantUML 1.2026.2 and the official SysML pilot 0.63.1 from release 2026-09.1.
Exact versions/hashes are recorded in environment.json and dependencies.txt. Bundled
minitest and pytest are executed; GoogleTest FetchContent and python-can are not claimed
tested. LLVM profiles are deleted/rebuilt for each coverage run; scope is six ECU source
files over unit and integration tests, not all experiments or the Python plant.

```sh
python3 -m venv .venv
.venv/bin/pip install -r results/v0.3.0/dependencies.txt
# Download the pinned public pilot distribution into a local tool directory:
curl -fL https://github.com/Systems-Modeling/SysML-v2-Pilot-Implementation/releases/download/2026-09.1/jupyter-sysml-kernel-0.63.1.zip -o /tmp/sysml-0.63.1.zip
unzip /tmp/sysml-0.63.1.zip -d /tmp/sysml-0.63.1
# Obtain PlantUML 1.2026.2 from Maven Central, then verify hashes against environment.json.
SYSML_PILOT_HOME=/tmp/sysml-0.63.1 PLANTUML_JAR=/path/to/plantuml-1.2026.2.jar scripts/run_v3.sh
```

The pilot is used as a Java library directly; its installer is not run and no global
kernel or application is changed. Java execution required escaping the session sandbox;
all source/output writes remain in the project or temporary tool directory. Initial
restricted-network installs failed; approved dependency downloads then succeeded. The
latest pilot release was inspected via GitHub's public releases API; fixed release URLs
and downloaded content hashes make later runs explicit rather than following latest.

The case manifest specifies all configurations, seeds and development/hold-out labels.
Its hash must remain identical on rerun. Controller/fusion thresholds were not fitted to
hold-out outcomes. Initial experiment outputs are retained as attempt1/2/3; the final
outputs correct instrumentation/metrics and scene-quality confidence as documented in
v0.3.0_verification.md. Old raw measurements are never rewritten to match the current model.
Distinct baseline noise outcomes exclude seed IDs and wall-clock timing in seed_analysis.json;
they do not establish statistically independent traffic diversity.

The current source defaults retain radar-only, primary-only operation for old scenario
files. Redundancy is enabled explicitly through perception='combined', backup_enabled=true
and imu_monitor=true in the frozen experiment configurations. This keeps configuration
comparisons explicit: v0.3.0 does not silently reinterpret the original FI01/FI02 inputs as
having extra hardware. Backup channels and sensors must not be described as physically
independent. ABI is now 3; rebuild C++ and Python together. The original CAN payloads remain
unchanged, while backup request transport enters a separate Brake ECU input with independent
E2E state. Achieved acceleration is the previous simulated plant interval, not ground-truth
friction supplied to the controller.

Reproducing v0.2.0 separately requires extracting its archive into a separate directory,
using its own ABI-2 library/bindings, and running its preserved pipeline. Do not run old
release tools against the v0.3.0 requirement database and overwrite historical evidence.
The LLVM runner uses macOS dylib/xcrun paths; Linux v0.3.0 is not verified here.
