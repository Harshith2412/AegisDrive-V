## Collision attribution

B's twelve failures comprise six stale authenticated delivery cases, four authenticated
counter-gap cases, and two same-epoch rollback/replay cases. C's six failures are the same
six stale-delivery cases. Every corresponding A configuration avoids collision. The evidence
supports attack-induced loss combined with rejection, native command timeout and missing
achieved braking, not a unique blame assignment to cryptography. Logical crypto processing
time is zero; host CPU duration cannot cause a simulated delay. Timeline wire age is measured
from the authenticated issued time as well as transport admission time; the attack injector
can hold a packet before re-admitting it, so these timestamps differ.

Persistent replacement/withholding on the sole usable path (or on both configured paths)
cannot be repaired by accepting stale data without weakening replay/deadline assurance.
Existing bounded C recovery already tolerates the tested gap/restart classes. The remaining
six C collisions must remain open unless a new fresh authenticated command can arrive.
